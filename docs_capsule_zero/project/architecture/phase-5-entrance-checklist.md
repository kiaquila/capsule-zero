# Phase 5 Entrance Checklist

## Status

Stage 1 mock-first entrance gate before product feature implementation.

## Purpose

The Phase 4 architecture direction is accepted. Phase 5 now starts with a mock-first Stage 1: product feature work may proceed once contracts, local quality tooling, scaffolds, provider adapter boundaries, and fixture-backed flows are in place. Real provider registration is an integration gate, not a precondition for writing the app.

## Sprint 0 Scope

Sprint 0 is the first implementation readiness slice of Phase 5. Feature sprints begin after the Stage 1 gates below are complete. Provider-dependent flows must not be called externally until their separate integration gates are complete.

## Mobile Payment Posture

MVP release posture is conservative:

- Web uses Lava.top for coin purchases.
- iOS and Android apps do not show Lava.top purchase CTAs or external payment links.
- Mobile apps show coin balance and transaction status after backend webhook fulfillment.
- App-store-specific purchase paths can be revisited after legal/store-policy approval.

## Exit Rule

Phase 5 Stage 1 feature sprints may start when the mock-first gates above are complete. If a feature requires real Supabase persistence, Google/Apple OAuth, Lava.top payment, Photoroom processing, or production deployment evidence, run the corresponding integration gate before that real provider flow enters QA, staging, or launch.
