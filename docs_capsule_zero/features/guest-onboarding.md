# Гостевой онбординг `/start`

Источник текущего UI: `alexey-golubtsov/krist-capsule` commit `8328dca30e2ee6aa69d699aff8f67bc6701abab3`.
Перенос 1 в 1 по задаче 2026-10-19; дополнение — смешанный гардероб. Канон: PRODUCT-PLAN §0.2, спека 055.

1. **Гардероб:** женский (19 пресетов), мужской (13) или смешанный (объединение 32). Смешанный использует существующие категории, включая платья, юбки и чинос.
2. **Вещи:** отметки «есть похожее», разделы верх/низ/платья/обувь/сумки, живой счётчик. Результат доступен при хотя бы одном совместимом образе. Исправление P2 из native review: если все роли есть, но цвета несовместимы, подсказка объясняет конфликт и предлагает ахроматическую замену; пустого «Добавь …» нет.
3. **Образы:** число, OPR, палитра, объяснение конфликтов, галерея и до трёх рекомендаций; «у меня есть» пересчитывает результат. Кнопка сохранения создаёт явный неизменяемый запрос и открывает существующий AuthPanel в режиме регистрации; у авторизованного пользователя сразу сохраняет.

CTA на главной ведёт на `/{locale}/start`; вход в шапке остаётся. EN/RU. Состояние — `cz-guest-v1` в localStorage, общее при смене языка. Reload восстанавливает прогресс; «начать заново» и `?fresh=1` сбрасывают его. Повреждённые/неизвестные/чужие для типа ID не допускаются в расчёт.

Фото-плитки сохраняют экран интереса из источника: без загрузки, сервера распознавания, цены или оплаты. «Хочу» записывает `cz-paid-interest-{kind}` только в localStorage. Серверных уведомлений нет. Это перенос концепта, а не выбранная модель монетизации.

**Сохранение в аккаунт (спека 056):** регистрация, вход и Google продолжают только явно запрошенное сохранение через `/account/guest/continue`. Обычный вход не импортирует оставленный локальный черновик. Явный intent хранится до подтверждения сервера; при ошибке доступны сообщение и повтор с тем же transferId. Успешный ответ ведёт на `/account/guest/{id}`. Чужой владелец не может повторить запрос или получить набор. PostgreSQL атомарно сохраняет неизменяемый упорядоченный снимок выбранных пресетов и добавляет вещи в `uncapsulated`, без дублей и перезаписи прежних статусов/избранного. Результат, OPR и образы строятся тем же `guest-v1` evaluator из сохранённых атрибутов и переживают очистку localStorage/новую сессию. Dashboard показывает ссылки на сохранённые наборы; My Items/Uncapsulated включают эти вещи, статусы и избранное хранятся в базе. Это отдельный гостевой набор, а не строгая капсула с обязательной палитрой. Следующие UX-изменения — отдельно по списку пользователя.

## Код и повторное использование

- `app/src/components/guest/` — отдельные гостевые экраны и редакционная раскладка; текущий authenticated WardrobeItemCard не соответствует исходной композиции.
- `app/src/features/guest/catalog-data.json` и `catalog.ts` — исходные 32 ID, названия, цвета, роли; Mixed — объединение.
- `app/src/features/guest/outfits.ts` — исходный расчёт в браузере; совместимость переиспользует `color-compatibility.ts`. Верх×низ×обувь или платье×обувь, до трёх разных совместимых сумок на базовый образ. OPR = образы / выбранные core+accessory вещи. Структурных слоёв в этом каталоге нет.
- `app/src/features/guest/state.ts` — проверка восстановленного состояния.
- `app/src/styles/guest.css` — геометрия источника; значения цветов вынесены в существующие либо точные reference-токены. Студийная подложка изображений — локальное разрешённое исключение; стеклянные панели сохраняются.
- `app/public/catalog/*.webp` — собственные сгенерированные вырезки, скопированные без изменений. Merchant-image import не включён.

Контракт: `api-spec.md`, OpenAPI и Go `internal/guest`; migration `0004_guest_progress.sql`. Канонический JSON каталога копируется в Go embed; `check:api-contract` проверяет совпадение. Фикстурный mock не используется для production сохранения.

Проверки: Playwright `specs/guest/`, landing hero, Chromium/WebKit; сравнение исходника и переноса на одинаковых размерах экрана. Методология и целевой account-save контракт сохраняются; этот срез не закрывает весь Stage 1.
